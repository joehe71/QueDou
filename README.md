# 雀斗 · QueDou

Finch 侧边栏里的三人斗地主：一位玩家和两位可独立配置的对手。对手始终使用 Finch 已启用的模型。独立实现牌型、回合和牌桌，不复用参考项目的代码或素材。

## 在 Finch 里试玩

需要 Node.js 20+ 和 Finch 1.8.1+。在仓库根目录执行：

```sh
npm run build
npx @finchtoys/minitools doctor .
npx @finchtoys/minitools add . --dev
```

在 Finch 的「小程序」中启用 **雀斗**，然后从左侧栏打开。开发安装链接到当前目录；改动后重新构建并重新打开页面（如仍显示旧版，重新加载小程序）。普通安装去掉 `--dev`。

也可在浏览器预览：构建后从 `dist/table` 启动本地静态服务器（例如 `python3 -m http.server 8080 --bind 127.0.0.1 --directory dist/table`），打开 `http://127.0.0.1:8080/`。Finch 安装版不需要启动服务器。

## 自己的座位托管

点手牌旁的「托管」，可选 Finch 模型代你叫分、出牌和过牌。托管只发送你的手牌和公开牌面。点「取消托管」立即拿回控制权；结算和页面重载后默认手动操作。

## 模型对手

首次打开优先为两席预选已启用的快速模型。点右上角的「对手」可以分别更换；正在思考的请求不会中断。需要授权小程序「会话」权限，不需要再填密钥；没有可用模型时不能开局。

每个模型通过独立的 Finch 后台会话，只收到自己座位的手牌、公开牌面和规则引擎生成的候选行动（最多 32 手出牌，跟牌时附过牌）。出牌请求会附上本局已出牌的点数统计；需要各手的座位和顺序时，可用 `quedou_turn` 的只读 `history` 动作查询。叫分请求不附出牌统计。对手和托管的模型请求固定关闭深度推理。雀斗不设决策截止，只显示已等待时长。模型直接调用 `quedou_turn`；规则引擎只接受本手所属会话的合法提交，收到后立即落牌，不等待文字回复。调用失败、返回无效或手动暂停会保留当前回合，可重试或更换对手模型。后台会话可能保留请求记录，云端模型会联网且可能消耗额度。

牌桌每一步都会写入 Finch 的小程序存储，切页时暂停尚未提交的模型请求，回来后从已保存的回合继续。旧网页存档仍可读时会自动迁移。

每次模型决策都会在 Finch 的「开发者工具 → 插件日志」写入一条 `[quedou:model-timing]` 记录，包含座位、模型、结果、总耗时及已观测阶段。`queueMs` 来自 Finch 的派发事件，`runnerMs` 是 Finch 报告的运行耗时，`afterDispatchMs` 是雀斗从收到派发事件到结束等待的耗时；没有观测到的字段留空。日志不写手牌、提示词或回复正文。

## 玩法

- 三人叫 1～3 分，不叫可过。最高分拿底牌先出；3 分立即定地主，三家不叫时，手动点击「重新发牌」。
- 点击手牌选牌；「提示」循环选择合法牌；跟牌时可过牌，连续两家过牌后由最后出牌的人重新领出。
- 农民共用胜负。炸弹、王炸、春天、反春天翻倍。结算后可直接再来一局。
- 规则约定：顺子、连对和飞机的主体限 3 到 A；带单可来自同一对子，带对须用不同点数的对子。无翅飞机优先；带单有多个合法主体时按最高主体判定。

## 开发

`npm test` 运行规则、回合及电脑完整对局测试。`src/table/` 是零依赖前端，`cards.js` 统一生成牌型和合法出牌，`round.js` 管理回合与结算，`computer.js` 只接收自己的手牌、公开的牌数和当前桌面信息。`finch.json` 声明本地 App View；`src/index.cjs` 使用 Finch 会话 API 接入模型，不需要额外部署服务。
